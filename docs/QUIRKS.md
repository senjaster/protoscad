# Голые фигурные скобки не создают область видимости

Например
```
x = "Original message";
module my_mod() echo(x);
{
    x = "Message inside bare brackets";  
    union() {
        x = "Message inside any module invocation";  
        my_mod();
    }
}
```

Этот код выводит Message inside bare brackets, логика следующая
1) сначала x присваивается значение "Original message"
2) Поскольку фигурные скобки не создают область видимости, то та же переменная x переопределяется 
   значением "Message inside bare brackets". (и выдается ворнинг, переопределяеть плохо)
3) Внутри union() создается новая локальная переменная x, которая скрывает глобальную, но не затрагивает ее значение.
   Поэтому при вызове my_mod() выводится "Message inside bare brackets" - значение из глобальной переменной

---
Аналогичное поведение наблюдается и при обращении к "детям из модуля"

```
module my_mod() { children(1); }

my_mod()
{
   echo("aaa");
   {
      echo("bbb"); // выполняется только это
      echo("ccc");
   }
}
```

Этот код выводит просто bbb, а не bbb и ccc, поскольку фигурные скобки просто раскрываются

Однако если добавить любой модуль, например union(), то выведется bbb и ссс:
```
module my_mod() { children(1); }

my_mod()
{
   echo("aaa");
   union() { // выполняется весь блок целиком
      echo("bbb");
      echo("ccc");
   }
}
```

# `$`-аргументы на вызовах builtin-модулей: НАШЕ РАСХОЖДЕНИЕ с OpenSCAD

Проверено на реальном OpenSCAD:

```
module mysphere() {
    sphere(1);
    translate([3,0,0]) children();
}
union()
{
    mysphere($fn=360) sphere(1);  // обе сферы мелкозернистые
}

union($fn=360) sphere(1);  // грубая сфера (!)

let($fn=360) sphere(1);  // мелкозернистая сфера
```

Логика OpenSCAD: присваивание `$fn=360` в аргументах вызова расширяет только контекст
самого вызываемого модуля. Именно поэтому работает идиома `sphere($fn=100)` — лист читает
специальную переменную из собственного контекста инстанцирования. Но дети builtin-модуля
вычисляются в области вызова без изменений, поэтому `union($fn=360) sphere(1)` дает грубую
сферу. У пользовательских модулей наоборот — расширенный контекст наследуется и телом,
и children() (обе сферы в `mysphere($fn=360)` мелкозернистые).

Наше поведение (намеренное упрощение): `$`-аргументы расширяют область всего поддерева
вызова для любого модуля, builtin или пользовательского. Отсюда единственное наблюдаемое
расхождение: `union($fn=360) sphere(1)` у нас дает мелкозернистую сферу.

Расхождение зафиксировано тестом `test_divergence_builtin_special_args_reach_children`
(tests/test_ast_evaluator.py); согласованные случаи — тестами
`test_user_module_special_args_match_openscad` и `test_let_special_args_match_openscad`.
